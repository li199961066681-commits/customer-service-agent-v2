# 工具接口说明

## 1. Tool 抽象

所有工具都实现统一的 `Tool` 类（`tools/base.py`）：

```python
class Tool:
    name: str              # 工具名（LLM 选择用的唯一标识）
    description: str       # 给 LLM 看的功能说明
    parameters: dict       # JSON Schema 参数规范（结构化输出约束）
    func: Callable         # 真正干活的可调用对象

    def __call__(self, **kwargs) -> str:
        """统一入口：参数校验 → 执行 → 返回 JSON 字符串"""
```

**为什么返回 JSON 字符串**：Agent 的消费端是 LLM，JSON 字符串既可以被 LLM 读取，也可以被代码 `json.loads` 还原——工具与 LLM 的边界统一为「字符串进、字符串出」。

## 2. 工具注册表

`tools/registry.py` 的 `build_tools()` 返回 `{名称: Tool}` 字典，同时导出 `tool_schemas`（4 个工具的 JSON Schema 列表），供 LLM 结构化选择工具。

## 3. 四个工具

### 3.1 rag_search(query, top_k=3)

- 功能：知识库语义检索
- 输入：`query` 用户问题；`top_k` 返回条数
- 输出：`{"results": [{"id","title","content","score","grounded"}]}`
- 底层：Chroma（MockEmbedding）或 MemoryBackend，8 条 KB 文档

### 3.2 query_ticket(ticket_id)

- 功能：按工单号查工单详情
- 输入：`ticket_id` 如 TK001
- 输出：`{"found": true, "id","user_name","title","status","created_at","note"}`
- 底层：SQLite `tickets` 表，参数化查询（防注入）

### 3.3 create_ticket(user_name, title)

- 功能：创建工单
- 输入：`user_name` 用户名；`title` 问题描述
- 输出：`{"ok": true, "id": "TK0003"}`（自增工单号）
- 底层：SQLite INSERT

### 3.4 update_ticket_status(ticket_id, status)

- 功能：更新工单状态
- 输入：`ticket_id`；`status` ∈ {待处理, 处理中, 已完成, 已关闭}
- 输出：`{"ok": true}` 或 `{"ok": false, "error": ...}`
- 底层：SQLite UPDATE

## 4. 调用链

```
tool_call 节点（LLM 结构化输出选工具+参数）
        → tools[name](**params)      # Tool.__call__
        → JSON 字符串
        → tool_result 写回 AgentState
        → respond 节点 _humanize_tool_result 转成用户话术
```

## 5. 可独立测试

每个工具不依赖 Agent 即可单测（见 `tests/test_agent.py` 第 3 组）：传参、看返回、验证副作用，这保证「工具可以单独替换」——未来把 SQLite 换成 MySQL 只动 `memory/long_term.py`。
